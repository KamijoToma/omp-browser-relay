# Standalone browser relay

Read [reference.md](reference.md) for the canonical connection, input, compatibility, and safety contract. Both files are self-contained when installed outside the repository. The running service exposes the same reference at `GET /docs` and machine-readable support/readiness at `GET /capabilities`, even before its extension connects.

1. Resolve the **configured** relay base URL from the active omp profile's `browser.relayUrl` setting or the user's explicit service configuration. Do not assume a port or accidentally use omp's auto-started bundled relay. Keep the standalone service running separately; configure the extension's port/token to match it. See the reference for the stock `PI_BROWSER_RELAY` override and `app.relay` selection.
2. Fetch `/capabilities` at that base URL. Backend support is not readiness: require `backend.ready` before driving tabs, or inspect `/json/version` for its 503 diagnostic. `boundaries.backgroundNativeFocusIsolation` is **false**: this real-page shared-control policy permits Chrome to activate the workspace during mouse input. Explain that typing or scrolling in another window may be interrupted unless the user has already accepted this tradeoff. If uninterrupted foreground work is required, do not pretend this policy provides it. Check the installed stock omp version; this relay transports CDP and does **not** install JavaScript methods in the client.
3. Use stock `browser.open`, `tab.drag`, `tab.mouseMove`, `tab.mouseDown`, `tab.mouseUp`, and other ordinary browser helpers. No new MCP server or relay-specific JavaScript facade is required. Open before using a tab handle, observe the actual page, and respect the user's authorization for signed-in actions. For [generic interactions](reference.md#generic-page-interactions), first identify one intended record/region and one visible, enabled target; use verified label/control or ARIA associations, not guessed nearby wrappers.
4. Coordinate shared work: all business tabs in the dedicated workspace are controllable, including user tabs moved into it. Moving a tab out revokes it. User focus does not pause automation; the user and agent can both interact. A dedicated window is **not** account/profile isolation or an exclusive-input lease.
5. Treat input coordinates as **viewport CSS pixels**, never desktop/screenshot physical pixels. Prefer selector-to-selector `await tab.drag("#source", "#destination")`. For custom paths, use explicit mouse calls and always release in `finally`, as shown in the reference. Re-read layout after navigation, scrolling, zoom, or re-render.
6. Do not use OS mouse/keyboard automation, synthetic DOM events, raw focus emulation, or custom CDP commands to bypass workspace scope. Actual focus emulation stays disabled, but Chrome can still activate its native window in response to trusted CDP mouse input. The relay does not restore the user's window after a focus steal. Browser permissions/dialogs, clipboard/native UI, and page-initiated focus/window requests add further exceptions.
7. Define and wait for an observable postcondition for each logical action; successful dispatch is not completion. Check DOM state or the requested business result, not framework globals or a fixed sleep. CAPTCHA recognition/acceptance is site-dependent; a real pointer trajectory never guarantees passing a real CAPTCHA. Stop or request user intervention for challenges that cannot be completed legitimately.
8. After any side-effectful action fails or times out, re-observe state and workspace ownership before continuing. Track **completed** (verified), **uncertain** (may have taken effect), and **remaining** (not attempted); reconcile uncertain steps and continue only the unfinished work. Never automatically replay a submission or a whole batch, or report a partial outcome as success.
9. Read and disclose only what the task needs. Prefer booleans, counts, and non-sensitive status fields over form values, full HTML, URLs, or request bodies; scope screenshots/recordings to approved content. This guidance cannot enforce global screenshot, HAR, or tool-output redaction.

Earlier connection, mouse/drag, screenshot, and lifecycle compatibility was verified with stock omp **18.12.2** and **18.4.2**: 18.12.2 can create owned work pages and has `browser.targets`; 18.4.2 must adopt an existing workspace business page, lacks `browser.targets`, and does not supply owned-page creation/close semantics. Seed its workspace using the extension's work-tab action. `app.target` is a URL/title matcher, not an opaque target ID. These observations do not establish version coverage for every generic interaction recipe or certify native-focus isolation; environment-specific headed proof is separate.
